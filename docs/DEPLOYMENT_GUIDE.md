# Deployment Guide

**Live app:** https://fitai-app-pink.vercel.app

FitAI runs on four free services:

| Part | Host | Configured by |
|---|---|---|
| Frontend | **Vercel** | `frontend/vercel.json` |
| Backend API | **Render** (free web service, Singapore) | `render.yaml` |
| Database | **Neon** (serverless PostgreSQL) | `DATABASE_URL` |
| Email codes | **Brevo** HTTPS API (300 emails/day free) | `BREVO_API_KEY`, `EMAIL_FROM` |

```
Browser ──► Vercel (React app) ──► Render (FastAPI) ──► Neon (PostgreSQL)
                                        ├──► Gemini (AI coach)
                                        └──► Brevo (login and verification codes)
```

The free Render server sleeps after about 15 idle minutes. The first request after that takes about a minute,
and the app shows a "waking up" message meanwhile.

The backend **refuses to start in production** if a setting is unsafe or missing (weak `JWT_SECRET`, SQLite
database, no email sender, no public `CORS_ORIGINS`). Render's log lists exactly what to fix. Pasted values are
trimmed automatically, and API keys are hidden (`[hidden]`) in every logged error.

## Secrets

Secrets live only in the Render and Vercel dashboards and in your local `backend/.env`, which is git-ignored.
Never commit them, paste them into chats, or show them in screenshots. If one is ever exposed, delete it at its
provider, create a new one and update Render.

## 1. Email: Brevo

Render's free plan blocks outgoing SMTP, so email goes over HTTPS.

1. Sign up at brevo.com (free plan).
2. **Settings → Senders, domains, IPs → Senders → Add sender** with your Gmail, then click the link Brevo emails you.
3. **Settings → SMTP & API → API keys → Generate a new API key.**

Brevo sends from its own address on your behalf (Gmail doesn't allow other services to use `@gmail.com`).
A brand-new Brevo account may take a few hours before Gmail starts accepting its mail; Brevo's
**Transactional → Logs** shows each email's status.

**Alternative: Gmail API** (sends from your own Gmail). FitAI supports it out of the box and uses it first when set:
create a Google Cloud project, enable the Gmail API, publish a consent screen, create a *Desktop app* client,
run `python3 scripts/gmail_token.py`, then add `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET` and `GMAIL_REFRESH_TOKEN` in Render.

## 2. Render (backend)

1. render.com → sign in with GitHub → **New → Blueprint** → choose this repo. Render reads `render.yaml`.
2. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string (`postgresql://…?sslmode=require`; FitAI adds the driver itself) |
   | `CORS_ORIGINS` | your Vercel address, plus `http://localhost:5173` for local testing |
   | `GEMINI_API_KEY` | from aistudio.google.com/apikey |
   | `BREVO_API_KEY` | from Brevo |
   | `EMAIL_FROM` | `FitAI <your.verified@gmail.com>` |

   `JWT_SECRET` is generated by Render, and `ENVIRONMENT=production` is set by the blueprint.
3. **Apply.** When it's live, `https://<service>.onrender.com/api/health` returns `"status":"ok"`.

## 3. Vercel (frontend)

1. vercel.com → sign in with GitHub → **Add New → Project** → import the repo.
2. Choose **Import single project** for `frontend` (Vite). Root directory: `frontend`.
3. Environment variable `VITE_API_URL` = `https://<service>.onrender.com/api`
4. **Deploy.**

## 4. Connect them

In Render → Environment, set `CORS_ORIGINS` to the Vercel address (with `https://`, no trailing `/`), then
**Save, rebuild, and deploy**. Open the site, try the demo, then register with a real email.

## Updating

Push to `main`. GitHub Actions runs every check, and Render and Vercel redeploy automatically.

Before pushing, run the same checks locally:

```bash
./scripts/test-all.sh
```

## Other options

- **Docker Compose (single server):** `docker compose up --build` with `ENVIRONMENT=production` and the same variables.
- **Paid Render plan (from $7/month):** no sleeping, and SMTP works, so a Gmail app password can be used instead of an API.
